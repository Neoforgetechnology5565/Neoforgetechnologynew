# Testing — what was run, against what, and what was real

Results below are from runs in the development environment (Firestore emulator, Chromium with the software rasteriser for WebGL). Nothing here claims testing in production, on other browsers, or with third-party commercial CAD/BIM software.

## Test files
There are **no photographs of real buildings and no third-party models** in the repository. Every sample is generated by code with **known geometry**, so the expected values are computed by hand or by construction — never copied from the program's own output and never adjusted to make a test pass:

| Sample | Ground truth |
|---|---|
| House plan (DXF, SVG, PNG) | 7 walls (4 exterior 0.30 m, 3 interior 0.15 m), 5 doors, 6 windows, 4 rooms with net areas 22.800625 / 13.250625 / 18.025625 / 18.025625 m² (hand-calculated from the wall coordinates) |
| House MEP overlay | ducts, equipment, diffusers, pipes, conduits and trays at known elevations and sizes |
| Drawing with defects | exactly 2 duplicates, 1 zero-length line, 1 almost-closed polyline (5 mm), 1 self-intersecting polygon, 1 stray element, 1 empty layer |

## Suites
| Suite | Command | Covers |
|---|---|---|
| Engine unit tests | `npx tsx src/lib/bim/{bim,export,input,cad,pointcloud,demos}.test.ts` | DXF parsing, plan interpretation, MEP, clash geometry, exporters (IFC written then re-read), SVG/raster, CAD analysis/conversion, point-cloud readers/filters/RANSAC, demonstrations 2–10 against ground truth |
| API tests | `node scripts/test-bim-api.mjs`, `test-bim-demos-api.mjs`, `test-bim-collab-api.mjs` | uploads, validation, processing, models, exports, downloads, settings/undo, authorisation, shares, roles, issues, comparison |
| UI tests | `node scripts/test-bim-ui.mjs`, `test-bim-demos-ui.mjs`, `test-bim-collab-ui.mjs` | Playwright against the running app: upload/samples, tabs, selection, measurement, parameters re-run, exports/downloads, role-restricted views, console errors |
| Independent validators | `python3 scripts/validate-bim-outputs.py` | IFC with ifcopenshell (schema + EXPRESS rules), DXF with ezdxf audit, GLB container structure |

## Real vs simulated
- **Real:** file parsing (own DXF parser, web-ifc, LAS/PLY/XYZ readers), geometry, clash maths, exports, persistence in Firestore (emulator), authorisation, rate limiting, file validation.
- **Synthetic:** all input files. A real-world drawing with unusual layer conventions, curved walls, hatches, xrefs or very large IFC models has **not** been tested.
- **Mocked:** nothing in the application code paths; the Firestore **emulator** stands in for the hosted database.
- **Not tested:** deployment, other browsers/devices, load/concurrency, files over a few MB, DWG/LAZ/E57 (rejected by design), accessibility audit beyond keyboard-reachable controls.

Findings during development that were test-expectation errors (not engine errors) were corrected in the test, with the reason noted in the commit history; engine errors were fixed in the engine. No expected value was changed to hide an engine error.

## Results of the final run (production build served with `next start`, Firestore emulator, Chromium software WebGL)

|---|---|
| Engine tests: `bim` 33, `export` 12, `input` 8, `cad` 13, `pointcloud` 11, `demos` 25 | **102 passed, 0 failed** |
| API: `test-bim-api` 25, `test-bim-demos-api` 14, `test-bim-collab-api` 12 | **51 passed, 0 failed** |
| UI: `test-bim-ui` 21, `test-bim-demos-ui` 15, `test-bim-collab-ui` 7 | **43 passed, 0 failed** |
| ifcopenshell validation of generated IFC (clean house, two-storey, revision B) | 0 messages; the deliberately flawed IFC yields exactly 1 message (the injected duplicate GlobalId) |
| `npm run build` | succeeded; `tsc --noEmit` clean; ESLint: no errors |

Notes: the in-memory rate limiter (30 sample loads / 10 min / IP) is real and was hit when all suites ran back-to-back against one server instance; the server was restarted between the API and UI runs. A defect found by reviewing a screenshot rather than by a test — `PATCH /issues/{id}` reset unrelated fields because zod 4 applies defaults inside `.partial()` — was fixed and is now locked in by a regression assertion in `test-bim-collab-api.mjs`.
